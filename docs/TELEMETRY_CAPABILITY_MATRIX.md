## Accuracy notes

- App Server notifications can be sparse. `account/rateLimits/updated` must be merged into the last full read response or followed by a refetch.
- `thread/tokenUsage/updated` reports cumulative and last breakdowns, but the schema does not promise that `last` is a whole-turn total.
- Receipt time is local metadata, not an exact Codex event timestamp when the notification does not include one.
- Raw protocol data is not retained by default, so future reinterpretation requires a new observation rather than reprocessing sensitive payloads.
- The live reset value observed on 2026-07-23 was plausible Unix seconds. This is evidence for that payload, not a schema guarantee.
- Threshold notifications are emitted only for persisted `reported_exact` used percentages and are deduplicated by bucket, raw reset value, and threshold.
- Missing metric values are represented as `null`. Numeric zero is retained and
  displayed only when a verified source explicitly reports zero.
- Presentation state is separate from accuracy: `live`, `waiting`, `disabled`,
  `unsupported`, `unavailable`, `error`, and `fixture` describe collection/setup
  state, while the four accuracy classes describe provenance.
- Alert severity is neutral below 50%, informational from 50% through 74%,
  warning from 75% through 89%, critical from 90% through 99%, and exhausted at
  100%.
